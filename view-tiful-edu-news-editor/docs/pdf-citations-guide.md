# PDF 인용과 실제 기사 문장 연결 보완

## 화면에서 확인한 문제

1. 검증 카드에는 '특히 확인해야 한다'가 있지만 현재 요약 입력칸에는 '미리 확인해야 한다'가 표시돼 있었습니다. 화면 일부만으로 이전 보고서와 현재 수정 내용의 차이인지, AI 인용의 차이인지 확정할 수는 없습니다.
2. 출입 통제와 입실 시각은 첨부 화면의 PDF 상단에 명시돼 있었습니다. 카드의 '인용한 근거를 실제 자료 발췌에서 확인하지 못했습니다'는 인용 연결 실패를 뜻합니다. 해당 내용이 거짓이라고 확인한 결과는 아닙니다.
3. 기존 코드는 공백을 한 칸으로 줄인 뒤 인용을 찾았습니다. PDF가 '학부모 포함'을 '학부모포함'으로 추출하거나 AI가 다른 발췌 번호를 지정하면 실제 자료에 내용이 있어도 연결되지 않을 수 있었습니다.

첨부 화면에는 '수험생 및 고사 관계자 외 외부인(학부모 포함) 및 차량 출입을 전면 통제'와 표의 '입실완료 / 09:30까지'가 보입니다. 같은 학년도·대상·조건을 유지해 기사에 풀어 쓴 표현은 근거와 대조할 수 있습니다.

## 이번 수정

- 최종 카드의 대표 문장은 실제 검사한 기사 인용을 표시합니다. AI가 바꿔 쓴 주장 요약은 'AI가 정리한 주장 보기' 안에 따로 표시합니다.
- '해당 기사 부분 수정'은 해당 인용만 선택합니다. 현재 입력칸에서 찾을 수 없으면 인용문과 현재 내용의 차이를 안내합니다. 입력 내용 자체를 자동 변경하지 않습니다.
- '특히·미리' 같은 확인 권유의 강조를 추가 규정으로 해석하지 않도록 AI 지침을 보완했습니다. 실제 날짜·규정·수치·대상은 계속 대조합니다.
- PDF 공백·줄바꿈만 다른 인용은 실제 자료 문자열로 복구합니다. 단어·숫자·문장부호 변경과 내용 재작성은 허용하지 않습니다.
- 발췌 번호가 틀려도 같은 자료에서 이번 검증이 실제 읽은 발췌에 해당 문구가 있으면 위치를 다시 연결합니다. 다른 자료나 읽지 않은 쪽에서 보충하지 않습니다.
- 자료마다 첫 발췌를 보존해 PDF 상단 안내 상자와 제목이 관련도 순위 때문에 제외되는 일을 줄였습니다. 전체 자료 읽기 분량 제한은 유지했습니다.
- PDF 안내 상자·표 열 이름·행의 값도 근거로 읽고, 입실 완료 시각과 시험 시작 시각을 구별하도록 AI 지침을 보완했습니다.
- 인용 보완 내역은 카드의 'PDF 인용·발췌 위치 연결 내역'에 표시합니다.

출입 통제 같은 규정은 근거 문서의 대상과 예외를 확인합니다. 통상적인 일이라는 이유만으로 승인하지는 않습니다. 이번 수정은 첨부 근거와 같은 의미의 문장이 표현·인용 위치 차이로 불필요하게 막히는 문제를 줄입니다.

## 기존 프로젝트에 적용

1. VS Code 서버 터미널에서 Ctrl+C로 서버를 멈춥니다.
2. ZIP을 임시 위치에 풉니다. 아래 파일만 기존 프로젝트의 같은 위치에 복사합니다.

| 위치 | 적용할 파일 |
| --- | --- |
| 프로젝트 최상단 | `citation_matching.py` 추가, `verification.py`·`final_review.py` 교체 |
| `static` 폴더 | `app.js`·`final.js`·`rewrite.js`·`index.html` 교체 |
| 선택 사항 | `README.md`, `docs`의 안내 문서, `tests/test_citation_matching.py` |

기존 `main.py`, `storage.py`, `human_review.py`, CSS, 폴더 구조와 설치 패키지는 그대로 사용합니다. `.env`, `data`, `.venv`는 유지합니다. ZIP에는 실제 API 키·기사 DB·업로드한 PDF·가상환경을 넣지 않았습니다.

3. 기존 프로젝트의 VS Code 터미널에서 실행합니다.

```powershell
.\.venv\Scripts\python.exe -m uvicorn main:app --reload --port 8002
```

4. http://127.0.0.1:8002 에서 Ctrl+F5로 새로고침하고 '저장한 기사'에서 현재 기사를 불러옵니다.
5. 코드 교체만으로 이전 검증 결과를 일치로 바꾸지는 않습니다. 새 규칙으로 결과를 받으려면 '최종 재검증 실행'을 한 번 누릅니다. 초안·근거를 바꾸지 않았다면 새로 등록하거나 원문부터 다시 검증할 필요는 없습니다.
6. 직접 기사 문장을 바꿨다면 먼저 '초안 저장'을 누릅니다. 근거를 변경했다면 화면이 안내하는 원문 검증·편집 결정·초안 확인을 진행합니다.
7. '해당 기사 부분 수정'을 눌러 실제 인용이 선택되는지 확인합니다. 현재 문장에 인용이 없으면 차이 안내가 나타납니다.
8. 출입 통제와 입실 시각에 표시된 실제 PDF 인용을 읽습니다. 남은 항목은 기존 항목별 사람 검토로 확인하고 현재 버전을 승인합니다.

## 검증 결과와 범위

```powershell
.\.venv\Scripts\python.exe -m unittest discover -s tests -v
```

- Python 자동 검사 110개 통과: 기존 94개와 이번 인용 관련 16개.
- 실제 FastAPI와 DOM으로 기존 사람 검토·최종 승인·다운로드 20개 그룹 통과.
- 문장 선택·현재 문장 차이·핵심 정보 이름과 값·PDF 연결 표시의 DOM 검사 8개 그룹 통과.
- 모든 AI 응답은 모의 응답을 사용했습니다. 실제 API 비용은 발생시키지 않았습니다.
- 이번 메시지에는 PDF 원본 파일 대신 화면 이미지가 첨부돼 있어, 화면의 문구와 PDF 추출 때 나타날 수 있는 문자열 차이로 재현했습니다. 사용자 PC의 원본 PDF와 실제 AI 결과는 업데이트 후 최종 재검증으로 확인합니다.

PDF OCR·스캔 인식 기능은 이번에 추가하지 않았습니다. 실제 자료에서 추출되지 않은 문장이나 AI가 단어를 바꿔 인용한 경우에는 확인을 보류하고 기존 사람 검토로 처리합니다. 인용 위치를 연결하는 과정에서는 별도의 AI 요청을 추가하지 않습니다.
