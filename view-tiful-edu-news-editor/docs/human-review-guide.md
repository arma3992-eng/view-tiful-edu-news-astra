# 조건 보완·확인 불가를 처리하고 현재 기사 버전 승인하기

검토자 이름과 전체 확인 입력은 AI 미해결 항목이 있어도 사용할 수 있도록 보완했습니다.
후속 PDF 인용·기사 문장 선택 업데이트는 `pdf-citations-guide.md`를 함께 확인하세요.
각 항목의 문제를 수정·재검증하거나 실제 근거·판단 기록으로 해결하면 현재 버전을 승인할 수 있습니다.
AI 판정을 임의로 일치로 바꾸지 않고 사람의 검토 기록을 승인에 함께 보관합니다.

## 올려주신 화면의 의미

| 화면 | 의미 | 처리 방향 |
| --- | --- | --- |
| 이미지 3: 준비물·전자기기·퇴실 유의사항이라는 기사 제목 | AI가 근거 인용을 읽은 발췌와 일치시키지 못함. 일반 안내 제목을 사실로 분류했을 가능성도 있음 | 구체적인 규정 단정이 없는 일반 제목이면 안내·분석으로 검토하고 이유 기록 |
| 이미지 4: 지정된 필기구 사용 | 규정의 실제 인용 확인 오류 | 해당 자료에서 사용 가능한 필기구를 읽고 정확한 발췌·판단 이유 기록 |
| 이미지 5: 안내의 핵심이 시간 엄수·답안 작성 방식이라는 표현 | '핵심'이라는 편집자의 평가를 객관적 사실처럼 표현한 문제 | '안내문은 시간 준수와 답안 작성 규정을 안내한다'로 수정하거나, 편집자 분석임을 명확하게 구분 |
| 이미지 6: 입실을 놓치면 건물 출입이 어려워진다는 표현 | 입실 완료 기준과 출입구 폐쇄 기준을 함께 적으라는 조건 보완 | 화면 근거 기준으로 '입실은 09:30까지 마쳐야 하며, 고사장 건물 출입구는 시험 시작 시각인 10시에 폐쇄된다'처럼 구분해 수정 |
| 이미지 7: 답안지 교체와 종료 30분 전 제한 | 해당 수치·제한의 실제 근거 인용 확인 오류 | 같은 학년도 자료에서 정확한 제한을 확인하고 발췌·판단 기록 |
| 이미지 8: 전자기기를 가방에 넣어야 한다는 문장 | 구체적인 규정의 근거 인용 확인 오류 | 자료의 규정 문장을 직접 읽고 근거 인용으로 기록 |
| 이미지 8: 답안지 교체 가능 시점 확인 권유 | 일반 확인 권유라면 사실 단정과 구분할 여지가 있음 | 단순 권유인지 직접 확인하고 안내·분석 판단 이유 기록. 실제 교체 규정은 별도로 근거 확인 |

위 시각·문장은 첨부 화면에 표시된 근거를 설명한 예시입니다. 실제 게시 전에는 자료의 학년도·대상·예외와 기사 전체 문맥을 확인하세요.
조건 보완은 새 자료가 항상 필요하다는 뜻이 아닙니다. 기존 근거가 충분하면 문장을 고치는 것으로 시작합니다.
기사에 이미 다른 곳에서 필요한 조건을 명확히 설명했다면, 해당 문맥과 근거를 함께 확인한 판단을 기록할 수 있습니다.

## 기존 앱 업데이트

1. 서버를 Ctrl+C로 종료하고 기존 `.env`와 `data`를 백업합니다. 원래 폴더는 그대로 둡니다.
2. ZIP을 별도 위치에 풀고 `education-news-editor` 안의 코드·화면·문서·검사 파일을 기존 프로젝트의 같은 위치에 복사합니다. 새 파일도 추가합니다.
3. 기존 `.env`, `data`, `.venv`는 삭제하거나 덮어쓰지 않습니다. ZIP에는 이 항목이 없습니다. 패키지 변경도 없습니다.
4. 기존 VS Code 터미널에서 다시 실행합니다.

```powershell
.\.venv\Scripts\python.exe -m uvicorn main:app --reload --port 8002
```

5. http://127.0.0.1:8002 에서 Ctrl+F5를 누르고 '저장한 기사'에서 현재 기사를 불러옵니다.
6. http://127.0.0.1:8002/api/health 의 `human_review_available: true`를 확인합니다.
7. `human_review.py`가 추가됐는지, 각 미해결 카드 아래에 '항목별 사람 검토'가 있는지 확인합니다.

같은 초안·근거·보고서 버전이라면 기존 최종 결과를 그대로 불러와 사람 검토를 시작할 수 있습니다.
기존 보고서로 사람 검토를 진행할 수 있습니다. PDF 인용 보완 규칙을 반영한 새 AI 결과를 받으려면 최종 재검증을 실행합니다.

## A. 실제 문장 수정이 필요한 경우

1. 해당 카드의 '해당 기사 부분 수정'을 누릅니다. 원래 초안의 제목·본문·핵심 정보·독자 안내 중 해당 편집란으로 이동합니다.
2. 기사 문장을 직접 수정하거나 사실 문장을 제외합니다. 다른 곳에 같은 표현이 반복되면 함께 확인합니다.
3. '초안 저장'을 누르고 '최종 재검증 실행'을 누릅니다.
4. 새 보고서의 남은 항목을 확인합니다. 이전 버전의 사람 검토·승인은 새 문장에 사용하지 않습니다.

검토 방법에서 '기사 문장 수정·제외 후 재검증'을 선택한 것만으로 현재 문장의 문제가 해결되지는 않습니다.
AI의 수정 제안은 자동으로 본문에 넣지 않습니다. 사람이 실제 문장과 문맥을 확인하고 수정합니다.

## B. 사실은 맞지만 AI의 인용·판정이 잘못된 경우

1. 항목별 검토 방법을 '실제 근거로 직접 확인'으로 고릅니다.
2. 이번 보고서에서 실제 읽은 자료·쪽·발췌를 고릅니다.
3. 표시된 내용에서 관련 문장을 드래그한 뒤 '선택 문장 또는 이 발췌를 근거 인용에 넣기'를 누릅니다. 선택하지 않으면 표시된 발췌 전체를 넣습니다.
4. 정확한 학년도·대상·수치·조건을 확인한 판단 이유를 5자 이상 적습니다.
5. 기사 문장과 전체 문맥을 실제로 뒷받침하는지 읽고 직접 확인 체크를 합니다.

입력한 인용은 서버에서도 실제 발췌와 비교합니다. 자료 선택이나 아무 문장 인용만으로 의미가 맞음을 보장하지 않으므로 사람이 내용을 판단합니다.
현재 보고서가 읽지 않은 곳에 근거가 있다면 자료를 추가·보완하고 필요한 검증을 다시 진행합니다.
이 경로 자체는 AI를 호출하지 않습니다.

## C. 사실이 아닌 일반 안내·분석인 경우

1. '사실 단정 없는 의견·분석·제안으로 확인'을 고릅니다.
2. 사실 단정이 아닌 이유를 구체적으로 적고 직접 확인 체크를 합니다.
3. 수치·의무·규정·조건·과거 사례가 들어 있다면 이 경로로 면제하지 말고 실제 근거를 확인하거나 기사 문장을 수정합니다.

근거와 불일치한 사실에는 이 선택지를 제공하지 않습니다.
일반 소제목·확인 권유를 AI가 사실로 잘못 분류하는 문제는 앞으로의 최종 검증 요청에서도 줄이도록 지침을 보완했습니다.

## 현재 버전 승인과 저장

1. 검토자 이름을 입력합니다. 현재 초안을 불러온 상태라면 미해결 항목이 있어도 이름을 입력할 수 있습니다.
2. 남은 항목별 검토를 마칩니다. 화면에 입력 완료·남은 항목 수를 표시합니다.
3. 기사 전체 사실·편집 내용·출처 및 이용 권한의 세 가지 검토 확인을 체크합니다.
4. '현재 기사 버전 승인'을 누르면 항목별 결정·실제 인용·판단 이유·검토자·시각을 승인에 함께 저장합니다.
5. HTML 또는 JSON을 내려받습니다. 사람이 확인한 근거도 출처에 넣고, JSON에는 항목별 검토 기록과 인용을 포함합니다.

항목별 검토 입력은 최종 승인 전에는 데이터베이스에 저장하지 않습니다. 작업 중 새로고침·기사 전환 시 저장하지 않은 입력이 있음을 알립니다.
승인 후 저장한 기사를 불러오면 검토 기록을 복원합니다. 새 초안·근거·보고서로 바뀌면 이전 승인은 무효입니다.
AI 판정 수는 원래 결과여서 확인 불가·조건 보완 수가 남아 보일 수 있습니다. 사람의 보완 결과는 각 항목과 승인 기록에 별도로 표시합니다.
기사 검사 누락·기사 인용 오류는 항목별 판단으로 우회하지 않습니다. 현재 기사 전체의 검증을 다시 마쳐야 합니다.
검토자 이름은 직접 입력한 기록이며 로그인으로 신원을 인증한 것은 아닙니다.

## 검증

```powershell
.\.venv\Scripts\python.exe -m unittest discover -s tests -v
```

최신 110개 모의 검사에서 기존 기능, 실제 인용 없는 승인 거절, 판단 이유·확인 필수 조건, AI 판정 보존, 사람 검토 후 승인·출처 내보내기와 변경 충돌을 확인했습니다.
실제 서버와 DOM에서도 이름 입력·편집란 이동·근거 선택·확인·승인·복원·다운로드를 확인했습니다.
실제 기사 판정은 본인의 자료를 직접 검토하면서 진행하세요.
