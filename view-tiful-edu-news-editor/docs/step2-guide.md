# 2단계 앱 업데이트와 사용법

## 이번 원문 인용 오류 수정 적용

현재 2단계 앱을 사용 중이라면 아래 네 파일을 교체합니다.

- verification.py
- storage.py
- static/app.js
- static/index.html

1. VS Code에서 서버 터미널에 Ctrl+C를 눌러 종료합니다.
2. 현재 프로젝트의 data 폴더를 복사해 보관합니다.
3. 압축 안 education-news-editor에서 위 파일을 찾아 현재 실행 중인 프로젝트의 같은 위치에 덮어씁니다.
4. data, .env, .venv는 그대로 보관합니다. 패키지 변경은 없습니다.
5. 프로젝트 터미널에서 아래 명령으로 서버를 다시 실행합니다.

    .\.venv\Scripts\python.exe -m uvicorn main:app --reload --port 8002

6. http://127.0.0.1:8002 에서 Ctrl+F5로 새로고침하고 '저장한 기사'를 선택합니다.
7. 등록된 PDF와 원문을 확인한 뒤 '원문 검증 실행'을 한 번 누릅니다.

원문에서 찾을 수 있는 인용의 결과는 저장하고, 찾을 수 없는 AI 발췌는 '원문 인용 확인 필요'로 분리합니다.
분리된 항목이 있으면 '일부 검증 · 확인 필요'를 표시합니다. 해당 항목은 네 가지 판정 수와 사실 판정에서 제외합니다.
모든 인용이 원문에서 확인되지 않으면 결과를 새로 저장하지 않고 오류와 AI 발췌 예시를 보여줍니다.
이때 이미 저장한 이전 결과가 있다면 보관합니다. 자동으로 API를 재호출하지 않습니다.

## 기존 앱에 적용

1. VS Code에서 서버가 실행 중인 터미널에 Ctrl+C를 눌러 종료합니다.
2. 현재 education-news-editor 폴더의 data 폴더를 복사해 보관합니다.
3. 압축 파일 안의 education-news-editor 내용물을 현재 education-news-editor 폴더에 덮어씁니다.
4. 기존 data, .venv, .env가 있다면 보관한 채 코드 파일을 교체합니다. 배포 ZIP에는 이 파일들이 포함되지 않습니다.
5. VS Code 터미널에서 패키지를 갱신합니다.

    .\.venv\Scripts\python.exe -m pip install -r requirements.txt

첫 실행 시 기존 데이터베이스에 자료·검증 결과 저장 구조를 추가합니다.
원문과 기존 근거를 삭제하거나 새 데이터베이스로 바꾸지 않습니다.

## AI 키 설정

OpenAI API 연결 방식입니다. 기본 모델은 gpt-5.4-mini이며 .env에서 변경할 수 있습니다.
본인의 OpenAI API 키는 https://platform.openai.com/api-keys 에서 준비합니다.
API 사용 시 해당 계정의 사용 요금·한도가 적용됩니다.

프로젝트 루트의 .env.example을 복사하여 이름을 .env로 바꿉니다.
VS Code에서 .env를 열고 아래처럼 키를 입력합니다.

    OPENAI_API_KEY=여기에본인의API키
    OPENAI_MODEL=gpt-5.4-mini

키를 이 대화에 보내지 않고 본인 PC에만 입력합니다.
키는 브라우저 코드나 데이터베이스에 저장하지 않으며 .gitignore에 등록되어 있습니다.
환경 변수가 이미 설정되어 있으면 그 값이 .env보다 우선합니다.

서버를 실행합니다.

    .\.venv\Scripts\python.exe -m uvicorn main:app --reload --port 8002

브라우저에서 http://127.0.0.1:8002 를 열거나 Ctrl+F5로 새로고침합니다.
오른쪽에 'AI 키 설정됨'이 나타나는지 확인합니다.
이 표시는 설정 파일에 키가 있다는 뜻입니다. 키의 유효성과 사용 가능 여부는 검증 요청 때 확인됩니다.

키 없이도 원문·URL·PDF 저장 기능을 사용할 수 있습니다.
키가 없으면 검증 결과를 만들지 않고 설정 안내를 표시합니다.

## 기존 기사로 시작

화면 아래 '저장한 기사'에서 이전에 저장한 기사를 선택합니다.
기존 원문과 근거를 그대로 불러옵니다.
주소만 등록한 근거는 검증 실행 시 내용을 읽으려고 시도합니다.
접근에 실패하면 입력된 근거 발췌가 있을 때 그 발췌를 사용하며 읽기 실패 상태를 표시합니다.
읽을 근거가 전혀 없으면 결과를 만들지 않고 PDF 또는 발췌 등록을 안내합니다.

## 기사 주소에서 원문 불러오기

1. '기사 주소'에 링크를 넣습니다.
2. '주소에서 원문 불러오기'를 누릅니다.
3. 제목·본문이 기사와 맞는지 확인하고 메뉴나 광고가 섞인 부분을 정리합니다.
4. '원문 저장'을 누릅니다.

로그인·접근 차단·자바스크립트로만 표시되는 기사에서는 자동 추출이 실패할 수 있습니다.
이때 기존 입력란에 제목·본문을 직접 붙여넣어 저장합니다.

## 공식 자료 주소 이용

1. 원문을 저장한 뒤 오른쪽 '자료 주소'에 링크를 넣습니다.
2. '주소에서 근거 불러오기'를 누릅니다.
3. 불러온 내용과 자료 이름을 확인합니다.
4. 필요한 문장을 선택하여 '선택한 문장 또는 이 페이지를 근거 내용에 넣기'를 누릅니다.
5. 자료 종류·이름을 확인하고 '근거 등록'을 누릅니다.

공식 공지 안의 첨부 PDF 링크까지 자동으로 따라가지는 않습니다.
PDF 파일을 다운로드해 첨부하거나 PDF 자체의 주소를 넣어주세요.

## PDF 첨부

1. 오른쪽 'PDF 첨부'에서 '파일 선택'으로 PDF를 고릅니다.
2. 'PDF 내용 읽기'를 누릅니다.
3. '추출한 페이지'에서 필요한 쪽을 고릅니다.
4. 텍스트와 표의 읽기 순서가 원본 PDF와 맞는지 확인합니다.
5. 필요한 문장을 드래그해 선택하고 '선택한 문장 또는 이 페이지를 근거 내용에 넣기'를 누릅니다.
6. 자료 이름·종류·출처 주소를 확인한 뒤 '근거 등록'을 누릅니다.

선택한 문장이 없으면 표시된 페이지 전체를 넣습니다.
여러 쪽을 차례로 선택하면 근거 내용에 쪽수와 함께 추가합니다.
자료 자체를 연결하므로 발췌를 넣지 않아도 PDF를 근거로 등록할 수 있지만 필요한 문장을 표시하면 관련 발췌를 고르는 데 도움이 됩니다.
'PDF 내용 읽기'는 자료를 보관한 상태이고, '근거 등록'을 눌러야 현재 기사에 연결됩니다.
등록된 자료에서 '첨부 PDF 열기'로 보관한 파일을 확인할 수 있습니다.

지원 범위: 20MB 이하, 1~200쪽의 텍스트 PDF.
스캔 PDF의 이미지에서 글자를 읽는 OCR은 이번 버전에 포함하지 않습니다.
쪽수는 PDF 파일의 첫 페이지를 1쪽으로 센 값이며, 문서에 인쇄된 쪽수와 다를 수 있습니다.

## PDF 버튼은 있는데 파일 정보가 보이지 않을 때

2단계 화면을 열었더라도 브라우저가 이전 app.js를 실행하면 PDF 버튼이 동작하지 않고 주소만 등록될 수 있습니다.
이번 수정본은 index.html의 app.js 주소에 버전을 붙여 이전 스크립트 캐시를 피합니다. app.js의 PDF 기능 코드는 그대로입니다.

1. 서버를 Ctrl+C로 종료합니다.
2. 압축 안 education-news-editor/static의 index.html과 app.js를 현재 실행 중인 프로젝트의 static 폴더에 덮어씁니다.
3. 기존 data, .venv, .env는 유지한 채 서버를 다시 실행하고 Ctrl+F5로 새로고침합니다.
4. 저장한 기사를 선택합니다. PDF를 고르고 'PDF 내용 읽기'를 눌렀을 때 파일 이름·쪽수·추출한 페이지가 나타나는지 확인합니다.
5. '근거 등록' 후 목록에 파일 정보와 '첨부 PDF 열기'가 나타나는지 확인합니다.

기존에 주소만 등록한 자료에는 PDF가 자동으로 연결되지 않습니다. 필요한 PDF를 다시 읽어 근거로 등록합니다.
여러 PDF는 같은 입력란에서 하나씩 읽고 등록하면 목록에 추가됩니다.

계속 이전 화면이 나오면 실제로 제공되는 파일을 확인합니다.

- http://127.0.0.1:8002/static/app.js?v=final-20261005 를 열고 Ctrl+F로 'pendingMaterial'과 '첨부 PDF 열기'를 찾습니다.
  두 문구가 없다면 서버가 다른 폴더의 app.js를 읽고 있습니다. 터미널의 프로젝트 경로와 덮어쓴 static 폴더의 위치를 맞춥니다.
- http://127.0.0.1:8002/api/health 에서 현재 최종 버전은 step이 5, verification_available이 true인지 확인합니다.
  이전 번호가 나오면 서버 코드와 화면을 함께 업데이트하세요. 최종 적용 방법은 docs/final-guide.md에 있습니다.
- 'PDF 내용 읽기' 후 오류가 나오면 화면의 오류 문구를 확인합니다. 파일 선택만으로는 PDF 내용이 보관되지 않습니다.

## 원문 검증 실행

원문과 근거 등록을 마친 뒤 상단 또는 오른쪽의 '원문 검증 실행'을 누릅니다.
기사의 학년도와 근거 자료의 적용 학년도도 확인하세요.
API 요청은 완료될 때까지 기다립니다. 실패하면 이유를 화면에 표시합니다.

결과 카드에 다음을 표시합니다.

- 원문의 실제 발췌와 확인할 사실 주장.
- 일치 / 불일치 / 조건 보완 필요 / 확인 불가.
- 판정 이유와 필요한 수정·추가 확인.
- 실제 근거 발췌와 PDF 쪽수 또는 웹 본문 위치.
- 검증 시간, 원문·근거 버전, 대조에 사용한 자료의 읽기 상태.

근거가 없다는 이유만으로 불일치 판정을 내리지 않도록 요청합니다.
AI의 원문 인용이 저장된 기사에서 확인되지 않으면 그 항목을 '원문 인용 확인 필요'로 분리하며, 다른 확인 가능한 항목은 저장합니다.
이 오류는 기사에 과거 사례나 트렌드가 있다는 이유로 발생하는 판정이 아닙니다. AI가 원문을 요약하거나 문장을 합쳐 인용한 경우도 여기에 해당할 수 있습니다.
분리된 항목에는 사실 판정을 표시하지 않습니다. '원문 인용 확인 필요'를 펼쳐 AI 발췌와 저장된 원문을 비교하세요.
모든 원문 인용이 확인되지 않으면 새 결과를 저장하지 않습니다. 오류를 없애기 위해 원문에 AI 발췌를 추가하지 마세요.
자료에 없는 문장을 인용하거나 근거 없이 일치 판정을 내리면 해당 판정을 확인 불가로 바꿉니다.
이 검사는 인용 존재 여부를 확인합니다. 인용이 실제 주장을 뒷받침하는지에 대한 AI 해석은 사람이 검토해야 합니다.

## 과거 사례·트렌드·편집자의 해석

원문에 이미 실린 과거 논술 사례나 추세도 검증 대상에 포함할 수 있습니다.
현재 공지만으로 확인되지 않는 과거 사실은 해당 연도의 자료를 추가 등록해 대조합니다.
자료가 없거나 적용 연도가 다르면 '확인 불가'로 남길 수 있습니다. 이 상태는 거짓이 확정됐다는 뜻이 아닙니다.

| 넣을 내용 | 확인할 근거와 표현 |
| --- | --- |
| 이전 논술고사 출제 사례 | 해당 대학·학년도의 기출 문제, 공식 해설, 전형 자료를 등록하고 연도를 명시합니다. |
| 논술 경향·트렌드 | 비교 기간과 대학·과목·문제 유형 등 비교 대상을 정합니다. 그 범위를 뒷받침하는 여러 연도의 자료·통계를 등록합니다. 한 사례만으로 전체 추세를 단정하지 않습니다. |
| 새로 추가할 사실 정보 | 원문과 별도로 출처를 연결하고, 재작성한 기사에 반영한 뒤 초안 전체를 재검증합니다. |
| 편집자의 해석·학습 제안 | '편집자 분석', '학습 제안'처럼 성격을 표시합니다. 대학의 공식 방침으로 표현하지 않고, 해석에 사용한 사실 근거는 검증합니다. |

추가 자료는 현재 화면 오른쪽의 근거 등록 입력란에서 등록합니다.
PDF는 파일 하나마다 'PDF 내용 읽기' 후 '근거 등록'을 누르면 기존 자료에 이어 추가됩니다.
트렌드는 자료 이름·위치·발췌에 비교할 연도와 문장을 표시하면 관련 근거를 고르는 데 도움이 됩니다.

현재 '원문 검증'은 저장된 원문에 있는 주장만 대조합니다.
새로 작성할 배경 설명을 넣기 위해 원문을 바꾸지 않고, 기사 재작성 단계의 추가 내용으로 다루는 방향입니다.
추가 내용 입력, 출처 연결, 사실·의견 구분, 초안 전체 재검증은 구현됐습니다. 최신 의견·인터뷰·자동 검색 사용법은 newsroom-guide.md에 있습니다.

## 검증 범위

등록한 근거와 자동 검색으로 실제 읽은 공개 본문을 대조합니다. 화면의 '자동 웹 검색·교차 대조 사용'을 끄면 등록 근거만 사용합니다. 검색 범위·요금·출처 확인 방법은 newsroom-guide.md에 있습니다.
자료 이름이나 사용자가 선택한 '공식 자료' 분류만으로 진위를 인정하지 않습니다.
최대 3만 자의 원문, 기사당 근거 10개, AI가 추출한 최대 40개 주장을 처리합니다.
긴 자료는 기사와 입력 발췌의 단어를 기준으로 관련 구간을 선택합니다.
선택한 발췌 수와 전체 발췌 수는 '대조한 자료와 읽기 상태'에서 확인합니다.
모든 페이지와 모든 사실이 검증되었다는 뜻으로 사용하지 않습니다.

원문 수정 또는 새 근거 등록 이후에는 이전 결과를 '재검증 필요'로 표시합니다.
검증 도중 다른 창에서 자료가 바뀌면 결과를 저장하지 않고 다시 실행하도록 안내합니다.
판정이 모두 일치여도 최종 승인이나 발행 기능으로 넘어가지는 않습니다.
기사 재작성과 최종 재검증·승인은 3단계 이후에 구현합니다.

## 확인 순서

1. 기존 저장 기사를 불러와 내용이 남아 있는지 확인합니다.
2. PDF를 첨부하고 페이지를 골라 근거로 등록합니다.
3. 새로고침 후 기사를 다시 선택하여 PDF가 연결되어 있는지 확인합니다.
4. AI 키를 설정하고 검증을 실행하여 카드별 이유와 근거를 확인합니다.
5. 원문을 수정·저장하여 '재검증 필요'가 표시되는지 확인합니다.
6. 서버를 종료했다가 다시 실행해 기사·첨부 파일·검증 결과가 남아 있는지 확인합니다.

자동 검사 실행:

    .\.venv\Scripts\python.exe -m unittest discover -s tests -v

이 검사는 실제 API 키를 사용하지 않습니다.
AI API의 성공·오류 응답을 모의하여 저장·표시·버전 처리를 확인합니다.
원문 인용 오류 일부·전체, 숫자·연도 변경, 과거·트렌드 주장의 근거 부족, 이전 결과 보존도 확인합니다.
배포 전 실제 기사와 공식 근거를 이용한 판정 품질 확인은 별도로 진행합니다.
