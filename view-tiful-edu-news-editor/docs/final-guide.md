# 최종 단계 — 기사 전체 재검증·사람의 승인·내보내기

기사 제작·검토용 핵심 흐름을 마무리한 버전입니다.
현재 업데이트는 항목별 사람 검토도 지원합니다. 이름 입력·조건 보완·근거 인용 오류 처리는 docs/human-review-guide.md를 먼저 읽어주세요.
기사 파일 다운로드까지 구현했습니다. 기존 뉴스 사이트 게시 연결과 운영용 로그인·배포는 별도입니다.

## 기존 프로젝트에 적용

1. VS Code 터미널에서 실행 중인 서버를 Ctrl+C로 종료합니다.
2. 기존 `.env`와 `data` 폴더를 백업합니다. `.venv`도 유지합니다.
3. 새 ZIP을 별도 위치에 풀고 안의 `education-news-editor` 폴더 내용을 기존 프로젝트에 복사합니다. 같은 이름의 코드·화면·문서를 교체하고 새 파일도 추가합니다.
4. `.env`, `data`, `.venv`를 삭제하거나 덮어쓰지 않습니다. ZIP에는 이 항목이 없습니다.
5. 기존 프로젝트 터미널에서 서버를 다시 실행합니다.

```powershell
.\.venv\Scripts\python.exe -m uvicorn main:app --reload --port 8002
```

6. http://127.0.0.1:8002 에서 Ctrl+F5를 누릅니다.
7. 상단의 '최종 검증·승인' 표시와 '최종 재검증·승인' 버튼을 확인합니다.
8. '저장한 기사'에서 작업하던 기사를 선택합니다. 원문·근거·첨부 PDF·편집 결정·초안이 유지되는지 확인합니다.

새 설치는 README의 환경·패키지 설치부터 진행합니다. 기존 사용자는 API 키를 다시 입력할 필요가 없습니다.
데이터베이스의 새 검증·승인 테이블은 시작 시 자동으로 추가합니다.

## 현재 기사에서 다음으로 할 일

1. 포함할 항목과 추가 자료를 확인하고 편집 결정을 저장합니다.
2. 제목·요약 두 문장·세부 항목·핵심 정보·독자 안내를 편집하고 '초안 저장'을 누릅니다.
3. 상단의 '최종 재검증·승인'으로 이동해 '최종 재검증 실행'을 누릅니다.
4. 사실 판정과 실제 근거 발췌를 확인합니다. '기사 전체 검사 범위 보기'를 펼쳐 제목부터 독자 안내까지 검사했는지도 확인합니다.
5. 미해결 항목을 수정·제외하거나 근거를 보완하고 저장·재검증합니다.
6. 기사 전체와 근거를 직접 검토한 뒤 이름과 세 가지 확인을 입력합니다.
7. '현재 기사 버전 승인'으로 승인 기록과 시각·버전을 저장합니다.
8. HTML 또는 JSON을 내려받습니다. HTML은 파일을 브라우저에서 열어 확인할 수 있습니다.

저장하지 않은 원문·근거 입력·편집 결정·초안이 있으면 마지막 단계 버튼이 잠깁니다.
최종 검증은 클릭할 때 사실 대조 API를 호출하며, 자동 웹 검색을 켜면 검색 요청도 실행합니다. 자동 재시도하지 않습니다. 승인·다운로드에는 추가 API 호출이 없습니다. 최신 검색·인터뷰·의견 사용법은 newsroom-guide.md에 있습니다.

## 상태에 따른 처리

| 상태 | 다음 행동 |
| --- | --- |
| 초안 저장 대기 / 수정 내용 저장 필요 | 초안 작성·저장, 입력 중인 근거 등록 또는 정리 |
| 초안 기준 변경 | 원문 검증·편집 결정을 확인한 뒤 초안 저장 |
| 최종 재검증 전 / 재검증 필요 | 현재 저장 초안의 최종 검증 실행 |
| 불일치 | 근거에 맞게 수정하거나 제외한 뒤 저장·재검증 |
| 조건 보완 필요 | 학년도·대상·범위·예외·기간 보완 후 저장·재검증 |
| 확인 불가 | 실제 근거를 직접 확인하고 인용·판단 이유 기록, 또는 근거 추가·문장 수정 후 재검증 |
| AI 근거 인용 오류 | 실제 읽은 자료 발췌로 사람이 확인하고 기록하거나 다시 검증 |
| 검사 누락·기사 인용 오류 | 현재 기사 범위·본문을 확인하고 재검증. 항목별 판단으로 우회 불가 |
| 재검증 완료 · 사람의 승인 대기 | 전체 기사·자료 직접 확인, 이름·검토 확인 입력 |
| 승인 완료 · 내보내기 가능 | 현재 승인된 HTML·JSON 다운로드 |

확인 불가를 체크만 해서 승인하는 기능은 없습니다. 분석·제안에 들어 있는 수치·정책·과거 사례도 사실 검증 대상입니다.
기존 자료로 사실을 확인했는데 AI만 잘못 판정했다면 실제 발췌·판단 이유·직접 확인을 항목별로 입력하고 승인에 함께 저장할 수 있습니다.
새 근거를 등록하면 원문 검증과 편집 기준도 바뀌므로 원문 재검증 → 편집 결정 확인·저장 → 초안 확인·저장 → 최종 재검증 순으로 진행합니다.

원문의 4문항은 보관하고, 실제 해당 대학·학년도 자료에서 5문항을 확인했을 때 수정 후보를 초안에 반영합니다.
자료 선택만으로 확인 완료가 되지 않으며, 근거가 모자라면 문항 수를 단정한 내용을 제외하거나 근거를 확보합니다.
개발 검사의 5문항 응답은 가상 자료입니다. 실제 대학의 문항 수를 이번 업데이트에서 확정한 것은 아닙니다.

## 검사 범위와 승인 기록

- 초안 전체 3만 자, 구성 부분 80개, 사실 검사 총 80개까지입니다. 긴 본문은 문장 경계를 우선해 나눕니다.
- 기사당 등록 근거 10개까지 대조합니다. 긴 자료는 관련 발췌를 선택하므로 모든 페이지를 읽었다고 표시하지 않습니다.
- 자료 읽기 시각·입력 발췌 사용 여부·선택 발췌 수와 읽기 오류를 최종 결과에 표시합니다.
- AI의 의미 판정·사실 추출은 완벽하지 않습니다. 사실 누락·학년도·대상·수치·조건·과장은 사람이 확인합니다.
- 사실 단정이 없는 의견·제안은 AI가 별도로 분류합니다. 전체 범위 검사와 사람의 검토는 여전히 필요합니다.
- 승인은 원문·근거·편집 결정·초안 버전, 원문 및 최종 보고서 ID, 저장 내용 해시에 연결합니다.
- 초안 저장은 같은 내용이어도 새 버전이므로 재검증·재승인이 필요합니다. 변경 없는 원문·편집 결정 저장은 유지합니다.
- 새 검증 보고서를 저장하면 이전 승인을 사용하지 않습니다. API 오류로 새 결과를 저장하지 못하면 기존 보고서와 기록은 유지합니다. 표시한 검증 시각·버전을 확인하세요.
- 검토자 이름은 직접 입력한 기록입니다. 인증·역할별 승인 권한은 운영용 로그인 단계에서 연결합니다.

서버가 다운로드 시 현재 승인 버전인지 다시 확인합니다. 화면의 승인 표시를 바꾸거나 오래된 승인 ID를 보내도 새 버전을 내려주지 않습니다.
이미 내려받은 파일은 그 시점의 승인 버전입니다. 내용 수정은 앱에서 저장·재검증·재승인하고 다시 내려받으세요.

## 출처와 첨부 자료

내보낸 기사에는 원문 제목·주소, 최종 사실 판정에 사용한 근거 이름·주소·위치, 승인 기록을 표시합니다.
원문 주소가 없으면 주소 미등록으로 표시하므로 게재 전에 앱에서 보완해주세요.
분석과 학습 제안은 따로 표시합니다. 학생·학부모·교사 안내는 넓은 화면에서 세 열, 작은 화면에서 세로로 배치합니다.
첨부 PDF 자체는 내보내기 파일에 넣지 않습니다. 공개 사이트에 게시할 때 별도로 첨부하거나 공개 자료 주소를 연결합니다.
출처 표기와 이용 권한은 각각 확인합니다. 앱의 체크로 이용 허가를 자동 취득하지는 않습니다.

## VS Code·터미널·브라우저 확인

VS Code에서 `final_review.py`, `exporting.py`, `static/final.js`, `docs/final-guide.md`, `tests/test_final_review.py`가 추가됐는지 확인합니다.
터미널에서 아래 모의 검사를 실행할 수 있습니다. 유료 API를 호출하지 않습니다.

```powershell
.\.venv\Scripts\python.exe -m unittest discover -s tests -v
```

94개 검사에 기존 데이터 업데이트, 항목별 사람 검토와 근거 인용 검사, 검증·승인 중 변경 충돌과 이전 승인 무효화가 포함됩니다.
http://127.0.0.1:8002/api/health 에서 `step: 5`, `final_review_available: true`, `approval_available: true`, `export_available: true`를 확인합니다.
`publishing_available: false`는 실제 공개 사이트 게시 연결이 별도라는 뜻입니다.
`human_review_available: true`가 항목별 사람 검토 업데이트를 뜻합니다.
최종 화면이 없으면 서버를 완전히 재시작하고 Ctrl+F5를 누릅니다. 기존 코드와 새 화면이 섞이지 않았는지 확인합니다.
실제 AI 판정 품질과 PC·모바일 크기·줄바꿈은 적용 후 직접 확인해주세요.
