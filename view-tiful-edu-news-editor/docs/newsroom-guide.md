# 의견·인터뷰·자동 검색 업그레이드

## 이번에 바꾼 동작

| 요청 | 변경 결과 |
| --- | --- |
| 기자 의견·주장을 허용 | 본문·추가 소재에 '기자 의견·주장'을 추가. 의견 자체와 그 안의 사실 전제를 구분하도록 검증 지침 보완 |
| 정식 보도자료 외 취재 근거 사용 | '인터뷰·취재 기록' 등록. 실제 발언, 대상·익명 표기, 역할, 날짜, 취재 방법 보관 |
| 분석·학습 제안 메뉴 활성화 | 원문 저장 후 유형·내용 작성 가능. 편집 결정을 바꾸는 중에도 초안 유형·본문 편집 가능 |
| 스스로 검색해 교차 검증 | 원문 검증·최종 재검증에서 공개 자료 검색 → 실제 본문 읽기 → 등록 자료와 함께 대조 |
| 최종 승인은 사람 | 모든 결과가 일치해도 자동 승인하지 않음. 검토자와 확인 사항·미해결 항목 검토 후 현재 버전 승인 |

기존 화면 구성·PDF 등록·저장한 기사·항목별 사람 검토·HTML/JSON 내보내기는 유지합니다.

## 기존 PC 앱에 적용

1. VS Code의 서버 터미널에서 Ctrl+C를 누릅니다.
2. 현재 프로젝트의 `data` 폴더와 `.env`를 별도 위치에 복사해 보관합니다.
3. 새 ZIP을 다른 폴더에 압축 해제합니다.
4. ZIP 안의 `education-news-editor` 내용물을 현재 `main.py`가 있는 프로젝트 폴더에 같은 위치로 복사합니다. 새 폴더를 프로젝트 안에 중첩해서 만들지 않습니다.
5. 기존 `data`, `.env`, `.venv`를 유지합니다. ZIP에는 실제 데이터·키·가상 환경이 없고 패키지 변경도 없습니다.
6. 현재 프로젝트 터미널에서 다시 실행합니다.

    .\.venv\Scripts\python.exe -m uvicorn main:app --reload --port 8002

7. 브라우저에서 http://127.0.0.1:8002 를 열고 Ctrl+F5를 누릅니다.
8. '자동 웹 검색·교차 대조 사용', 자료 종류의 '인터뷰·취재 기록', 추가 소재의 '기자 의견·주장'을 확인합니다.

`static/app.js`만 바꾸면 이번 기능을 적용할 수 없습니다. 전체 ZIP의 코드 파일을 함께 복사하세요.
새 루트 파일 `web_research.py`, `evidence_catalog.py`, 새 화면 파일 `static/research.js`가 필요합니다.
첫 실행 때 취재 메타데이터 저장 열을 추가하며 기존 기사·근거·PDF는 보관합니다.

기존 `.env`에 API 키가 있으면 다시 입력하지 않아도 됩니다. `WEB_RESEARCH_ENABLED`가 없으면 자동 검색을 기본으로 켭니다.
모델도 기존 `OPENAI_MODEL`을 그대로 사용합니다. 별도의 검색 모델 설정 `OPENAI_WEB_MODEL`은 선택 사항입니다.
현재 기본 모델은 `gpt-5.4-mini`이며 이번 업데이트에서 모델을 바꾸지 않았습니다.

서버 확인 주소 http://127.0.0.1:8002/api/health 에서 `web_search_available: true`, `interview_available: true`를 확인할 수 있습니다.
이 값은 기능이 설치됐다는 뜻입니다. 실제 검색 API 호출 성공을 미리 보장하는 값은 아닙니다.

## 사용할 내용의 유형

| 유형 | 예시 | 검토 방법 |
| --- | --- | --- |
| 사실·배경 | 실시일, 준비물 규정, 이전 논술 문항 수, 합격률 추세 | 기사와 같은 학년도·기간·대상·조건의 실제 자료 대조 |
| 편집자 분석 | '이 변화는 준비 방향에 영향을 줄 수 있다' | 해석임을 표시하고 분석에 사용한 실제 규정·수치 등은 따로 대조 |
| 기자 의견·주장 | '입시 정보는 더 이해하기 쉽게 제공돼야 한다고 본다' | 가치 판단 자체에 근거 부족 판정을 만들지 않도록 요청. 사실 전제는 계속 대조 |
| 학습 제안 | '충분히 쉬면서 준비해보자' | 준비 권유와 실제 의무·규정을 구분. 제안에 들어간 날짜·준비물 규정은 대조 |
| 인터뷰·취재 | 'A 교사는 준비 부담이 크다고 말했다' | 실제 발언 기록·대상·날짜 확인. 개인의 평가를 전체 집단의 사실로 일반화하지 않음 |

유형 이름만 바꾼다고 사실 검증을 통과하지 않습니다. 예를 들어 기자 의견에 '합격률이 20% 높아졌다'가 들어 있으면 그 수치는 사실 검증 대상입니다.
원문에 있던 의견을 새 기사에 사용할 때는 '추가 내용 넣기'에서 해당 유형으로 넣거나 초안에 직접 작성하세요.
AI 작성은 선택한 사실 소재와 추가 소재만 사용합니다. 보류·제외한 사실을 원문 전체에서 복원하지 않습니다.

## 인터뷰 등록

1. 오른쪽 '근거 자료 등록'에서 자료 이름을 입력합니다.
2. 자료 종류를 '인터뷰·취재 기록'으로 고릅니다.
3. 인터뷰 대상·익명 표기와 날짜를 입력합니다. 소속·역할은 선택 사항입니다.
4. 취재 방법을 대면·전화·이메일·서면·기타 중에서 고릅니다.
5. '대조할 근거 내용'에 실제 발언·취재 기록을 입력하고 '근거 등록'을 누릅니다.
6. '기사 재작성 → 추가 내용 넣기'에서 '인터뷰·취재'를 고르고, 등록한 취재 근거를 연결합니다.

인터뷰 자료 주소나 PDF만 넣고 실제 발언 기록을 비우면 등록할 수 없습니다.
URL이 함께 있어도 취재 기록의 발언을 웹페이지 내용으로 교체하지 않습니다.
공개된 인터뷰 기사는 '언론 기사'의 주소 자료로 등록해서 사용할 수도 있습니다.
비공개 인터뷰가 실제 있었는지 공개 검색으로 확인할 수는 없습니다. 취재 기록을 사람이 확인해야 합니다.
발언이 존재한다는 사실과 발언 속 주장이 객관적으로 사실이라는 판단은 구분합니다.

'등록 입력 비우기'는 아직 등록하지 않은 입력을 지웁니다. 이미 저장한 근거는 보관됩니다.
근거를 추가하면 기존 검증은 재검증 필요 상태가 되므로 원문 검증을 다시 실행하세요.

## 지금 저장한 기사로 진행

1. '저장한 기사'에서 현재 기사를 불러옵니다.
2. '자동 웹 검색·교차 대조 사용'이 켜져 있는지 확인합니다.
3. 필요한 비공개 취재 기록을 등록합니다. 공개 자료는 먼저 일일이 내려받지 않아도 됩니다.
4. '원문 검증 실행'을 누릅니다. 검색과 본문 읽기·사실 대조가 끝날 때까지 기다립니다.
5. 결과의 실제 인용과 출처 링크를 열어 판정을 확인합니다. 확인되지 않은 항목은 보류·수정하거나 근거를 확인해 포함합니다.
6. '추가 내용 넣기'에서 의견·분석·학습 제안·인터뷰 소재를 작성합니다. 원문 검증에서 자동 검색한 근거도 연결할 수 있습니다.
7. '편집 결정 저장' 후 'AI로 초안 작성' 또는 '직접 초안 작성'을 진행합니다.
8. 제목·요약·항목 내용·유형을 확인하고 '초안 저장'을 누릅니다.
9. '최종 재검증 실행'을 누릅니다. 최종 기사 전체의 공개 사실을 새로 검색하고 자료와 대조합니다.
10. 미해결 항목을 처리한 뒤 사람이 현재 기사 버전을 승인하고 HTML·JSON을 내려받습니다.

원문 검증 전에도 분석·의견·제안의 유형·내용은 입력할 수 있습니다. 검증 후 '편집 결정 저장'을 눌러야 서버에 보관됩니다.
검증 전의 화면 입력은 새로고침하면 사라질 수 있으므로 검증을 마치고 저장하세요.
기존 기사의 최종 재검증·승인을 진행하는 경우 현재 원문 검증과 편집 결정이 유효하면 새 초안을 만들지 않고 저장한 초안을 다시 검증할 수 있습니다.
새 원문 검증 결과가 저장되면 이전 결정·초안은 새 결과에 맞게 확인하고 저장해야 합니다.

## 자동 검색 결과 읽기

- 원문 검증과 최종 재검증에 각각 '자동 웹 검색' 출처 목록을 표시합니다.
- 검색된 링크의 본문을 서버에서 다시 읽습니다. 검색 요약·모델이 임의로 적은 주소만으로 사실 근거를 만들지 않습니다.
- 기관 원자료와 별개 출처를 우선 찾도록 요청합니다. 한 번의 검증에서 검색 도구 호출 최대 4회, 후보 본문 읽기 최대 6개로 제한합니다.
- '본문 읽음'과 '본문 읽기 실패'를 구분하며, 실패한 자료는 근거 인용에 사용하지 않습니다.
- 주장별로 실제 인용 근거 수와 사이트 수를 표시합니다. 같은 사이트나 본문이 같은 자료를 여러 독립 근거라고 세지 않습니다.
- '복수 사이트'는 여러 사이트의 본문을 인용했다는 뜻입니다. 같은 보도자료 전재·보도 내용을 재인용한 기사인지는 사람이 추가 확인합니다.
- 하나의 공식 안내만으로 충분히 뒷받침되는 사실도 있습니다. 무조건 출처 두 개를 채우는 방식은 아닙니다.
- 단일 근거·자료 충돌·다른 학년도·발췌 부족은 AI가 판단 이유에 적도록 요청합니다. 실제 인용의 의미는 사람이 확인합니다.
- 긴 자료는 앞부분과 관련 발췌를 선택해 대조합니다. 파일·웹페이지의 모든 문장을 검사했다는 뜻은 아닙니다.

검색 결과는 검증 보고서에 읽은 시점·주소·본문 발췌와 함께 보관됩니다. 저장 기사를 다시 불러올 때 검색을 재실행하지 않습니다.
원문·근거·기사 또는 최종 검증 결과가 달라지면 이전 승인으로 내보낼 수 없습니다.

## PDF를 직접 넣어야 할 때

공개 PDF의 주소에서 내용을 읽을 수 있으면 자동 대조합니다.
접근 차단, 로그인 자료, 검색되지 않는 첨부 파일, 이미지 위주 PDF는 직접 등록이 필요할 수 있습니다.
이미지 위주 PDF는 현재 자동 OCR이 없으므로 정확한 문장을 직접 입력하거나 텍스트 PDF를 준비하세요.
기존의 'PDF 내용 읽기 → 근거 등록'으로 자료를 여러 개 연결할 수 있습니다.
등록 자료가 검색한 최신 자료와 충돌하면 적용 학년도·대상·시점을 확인하고 기사 문장을 수정하세요.

## 사람이 최종 판단하는 방법

| 결과 | 다음 행동 |
| --- | --- |
| 근거와 불일치 | 실제 규정·수치·대상을 확인해 기사 문장을 수정하거나 사실을 다시 확인할 실제 근거 기록 |
| 조건 보완 필요 | 누락된 대상·기간·예외를 보완해 저장·재검증. 실제로 조건이 이미 충분하면 근거와 판단 이유 기록 |
| 확인 불가 | 추가 자료 등록·재검증, 기사에서 보류·제외, 또는 실제 읽은 근거를 사람이 확인해 기록 |
| 순수 의견·분석·제안을 사실로 오분류 | '사실 단정 없는 의견·분석·제안으로 확인'을 선택해 판단 이유 기록 |
| 검사 범위 누락·기사 인용 오류 | 현재 초안 전체를 재검증. 항목별 사람 판단만으로 검사 누락을 해제하지 않음 |

근거와 직접 불일치한 사실은 의견·분석으로 분류해서 해제할 수 없습니다.
AI가 '일치'로 판정해도 검토자 이름과 사실·편집 내용·출처 및 권한 확인 세 항목이 있어야 승인됩니다.
인터뷰 발언과 기사에 사용한 출처는 승인된 기사 내보내기에도 남습니다. 승인 버튼은 AI API를 호출하지 않습니다.

## API 사용료와 설정

자동 검색을 켜면 검색 요청과 사실 대조 요청을 실행합니다. 검색 도구 호출과 모델 사용에 요금이 발생합니다.
검증을 다시 실행하면 새 검색 요청을 합니다. 오류가 표시되면 내용을 확인한 뒤 다시 실행하세요.
화면에서 '자동 웹 검색·교차 대조 사용'을 끄면 그 실행은 등록한 근거만 대조합니다.
검색을 사용하지 않고 원문 검증을 실행할 때는 읽을 수 있는 등록 근거가 필요합니다.
서버 초기 선택을 끄려면 기존 `.env`에 `WEB_RESEARCH_ENABLED=false`를 넣고 재시작합니다.
등록 근거 없는 추가 사실을 편집 소재로 사용할 때는 `WEB_RESEARCH_ENABLED=true`를 유지하고 최종 검색·대조를 실행하세요.
검색 모델이 도구를 지원하지 않으면 실패를 표시하고 등록 근거로 대조합니다. 모델을 몰래 바꾸거나 결과를 지어내지 않습니다.

공식 구현 문서: https://developers.openai.com/api/docs/guides/tools-web-search

## 확인 결과와 다음 확인

138개 자동 검사와 41개 화면 연결 검사를 통과했습니다. 외부 AI·검색 응답은 모의 응답입니다.
